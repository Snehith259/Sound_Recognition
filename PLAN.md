### 2.4 What “R²” means in this repository

`eval/metrics.py` computes:

```text
r2Probability = 1 − SSE / SST
one_hot      = one-hot matrix of true labels (n × 50)
SSE          = sum((one_hot − predicted_probabilities)²)
SST          = sum((one_hot − mean(one_hot))²)
```

This is a **probability-vector reconstruction R²**, not a regression R² of a continuous target. It is a diagnostic that rewards calibrated probability mass on the correct class. It is not accuracy, and it must not be presented as “R² accuracy”.

- A perfect, fully confident classifier would score 1.0.
- A uniform 50-class classifier scores about 0.0.
- A confidently wrong classifier can score negative.
- The legacy MLP scored **−0.055**; AST scores **0.8798** (fold-1) and **0.8813** (external unambiguous).

**Do not optimize R² directly.** Maximizing it encourages overconfidence and can worsen ECE. Report it with the label “Probability R² (diagnostic)” and show top-1, top-5, and ECE next to it.

Reference implementation (adapt to the file’s existing imports and typing):

```python
def _load_ast_engine() -> Dict[str, Any]:
    """Load the local ESC-50 AST checkpoint once. No network I/O."""
    global _AST_ENGINE
    if _AST_ENGINE is not None:
        return _AST_ENGINE
    with _AST_LOCK:
        if _AST_ENGINE is not None:
            return _AST_ENGINE

        from transformers import AutoFeatureExtractor, AutoModelForAudioClassification

        kwargs = {
            "cache_dir": str(AST_CACHE_DIR),
            "local_files_only": True,
            "revision": AST_REVISION,
        }
        feature_extractor = AutoFeatureExtractor.from_pretrained(AST_MODEL_ID, **kwargs)
        model = AutoModelForAudioClassification.from_pretrained(AST_MODEL_ID, **kwargs)
        model.eval()

        name_to_id = {category["name"]: category["id"] for category in ESC50_CATEGORIES}
        label_map: Dict[int, int] = {}
        for raw_index, label in model.config.id2label.items():
            output_index = int(raw_index)
            key = str(label).strip().lower().replace("-", "_").replace(" ", "_")
            if key in name_to_id:
                label_map[output_index] = name_to_id[key]
            elif key.startswith("label_") and 0 <= output_index < len(ESC50_CATEGORIES):
                # Generic LABEL_n checkpoints use canonical ESC-50 order.
                label_map[output_index] = output_index
        if len(label_map) != len(ESC50_CATEGORIES):
            raise RuntimeError(
                f"AST label mapping incomplete: {len(label_map)}/{len(ESC50_CATEGORIES)}"
            )

        _AST_ENGINE = {
            "feature_extractor": feature_extractor,
            "model": model,
            "label_map": label_map,
            "sampling_rate": AST_SAMPLE_RATE,
            "model_id": AST_MODEL_ID,
            "revision": AST_REVISION,
        }
    return _AST_ENGINE


def _ast_probabilities(y: np.ndarray, sr: int) -> np.ndarray:
    """Mean class probabilities over 5 s windows. No filename or metadata use."""
    engine = _load_ast_engine()
    if sr != AST_SAMPLE_RATE:
        y = librosa.resample(
            np.asarray(y, dtype=np.float32), orig_sr=sr, target_sr=AST_SAMPLE_RATE
        )
    y = np.asarray(y, dtype=np.float32)

    window = int(AST_SAMPLE_RATE * ANALYSIS_WINDOW_SECONDS)
    hop = int(AST_SAMPLE_RATE * ANALYSIS_WINDOW_HOP_SECONDS)
    if y.size <= window:
        starts = [0]
    else:
        starts = list(range(0, y.size - window + 1, hop))
        final_start = y.size - window
        if starts[-1] != final_start:
            starts.append(final_start)
        if len(starts) > MAX_ANALYSIS_WINDOWS:
            starts = starts[:MAX_ANALYSIS_WINDOWS - 1] + [final_start]

    accumulated = np.zeros(len(ESC50_CATEGORIES), dtype=np.float64)
    for start in starts:
        chunk = y[start:start + window]
        if chunk.size < window:
            chunk = np.pad(chunk, (0, window - chunk.size))
        inputs = engine["feature_extractor"](
            chunk, sampling_rate=AST_SAMPLE_RATE, return_tensors="pt"
        )
        with torch.no_grad():
            logits = engine["model"](**inputs).logits[0]
        probs = torch.softmax(logits, dim=-1).numpy()
        mapped = np.zeros(len(ESC50_CATEGORIES), dtype=np.float64)
        for output_index, category_id in engine["label_map"].items():
            mapped[category_id] = probs[output_index]
        accumulated += mapped

    accumulated /= max(1, len(starts))
    accumulated /= max(float(accumulated.sum()), 1e-12)
    return accumulated.astype(np.float32)
```

Key details that must match the measured protocol:

- Resample to **16 kHz** only. Do **not** peak-normalize the waveform for AST; the feature extractor applies its own fixed mean/std normalization. The measured 85.71% external result used no peak normalization.
- Use **5 s windows**, **2.5 s hop**, **max 12 windows**, include the final aligned window. For clips shorter than 5 s, pad with zeros.
- Average **probabilities**, then renormalize. This matches the measured external result.
- Map labels **by name**, not by assumed index. Fall back to canonical order only for generic `label_N` checkpoints.
- Do not use the legacy `acoustic_classifier.pt` as a fallback.
- **Fix the PyTorch thread setting.** The current module calls `torch.set_num_threads(1)` at import. That is fine for the tiny four-model CNNs but makes AST take ~2.3 s per 5 s window on this CPU. Use `SOUNDSENSE_TORCH_THREADS=4` (or `min(4, os.cpu_count())`) and re-benchmark. Four threads measured ~0.70 s/window. A 12-window request is then ~8.4 s, still within the 30 s Express subprocess timeout.
- `engine` string should be `"ast-esc50"`, `confidenceType` should be `"model_softmax"` (not “calibrated” unless temperature scaling is actually fitted).
- Do not label AST as `resnet18`, `vgg16`, `sresnet`, `cnngru`, or `ensemble` to avoid adding a UI option. That would be a false claim about the architecture. Add a separate `ast` key and one dropdown option.
- `oodScore` remains `1 − top_prob`; do not claim it is a calibrated OOD probability. Keep `isOutOfScope=False` for normal clips and let the silence/tone gates and user threshold provide safety. A separate OOD gate can be added only after §7.

## 7. Calibration, confidence, and OOD policy

### 7.1 Calibration

- AST’s measured ECE is already good: 0.0384 on fold-1, 0.0544 on external unambiguous clips.
- Do not fit a temperature on external dev. That leaks evaluation data into the product.
- If temperature scaling is desired, fit it on an ESC-50 validation fold (or a held-out calibration split) and store the temperature in the checkpoint metadata. Report ECE before and after.
- The four architecture models already fit temperature on validation folds in `eval/train_cv.py`; keep that.

### 7.2 Selective prediction

Display/report:

- accuracy at confidence ≥ 0.90 and coverage,
- accuracy at confidence ≥ 0.80 and coverage,
- mean confidence on correct vs wrong.

Do not claim “95% accuracy” without the coverage number. AST’s external 95.65% is at 41.07% coverage; that is a selective-prediction result, not overall accuracy.

### 7.3 OOD

- Keep the existing silence and pure-tone gates.
- `1 − max_prob` is a useful ranking score (AUROC 0.8558), but it is not a calibrated OOD probability.
- Do not hardcode an OOD rejection threshold from the small dev set. If a production threshold is required:
  - choose it on a larger, independent calibration set,
  - report the false-rejection rate on in-scope audio,
  - report the rejection rate on OOD audio,
  - keep it configurable and documented.
- The UI’s confidence-threshold slider is not an OOD classifier. Label it as a user-controlled confidence cutoff.

### 7.4 R² display rule

- Label it “Probability R² (diagnostic)”.
- Never show it as “R² accuracy” or “model quality score”.
- Never tune the model to maximize it directly.
- Explain in one sentence: it measures how close the predicted probability vector is to the one-hot truth; it is not a regression R².
